Your SSH client. One gateway. Native Incus.

incus.ssh is a small Go service beside Incus. Your username and public key select a fixed project. The gateway turns a few management commands into checked Incus operations.

Type ssh melon in the management prompt and your terminal connects to that guest through incus exec. There is no second SSH daemon to configure inside the environment.

These are unprivileged Linux containers, not hardware VMs. They feel like persistent little machines, but share the host kernel. No Docker daemon or nested containers are involved.

Use it when you want less ceremony.

  • You already have a Linux server. Put spare capacity to work without building a control plane.
  • Your projects need a real Linux userland. Package managers, compilers and long-lived working directories belong here.
  • You like the exe.dev workflow. Keep the quick SSH experience, with your own Incus host underneath.
  • You're running trusted personal workloads. Development, experiments and hobby services are the intended fit.

Choose something else when the boundary matters more.

  • You need VM-grade isolation. Containers share a kernel. This is not a hostile-code or untrusted-tenant security boundary.
  • You need a managed production platform. There is no HA, SLA, automatic backup service or billing system.
  • You need Windows, nested Docker or a multiuser cloud. Those are deliberately outside the current scope.
  • You want public hosting to be automatic. Access starts private. Public routing is an explicit operator/user decision, not a side effect of creation.
