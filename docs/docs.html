Documentation

Everything needed to build, install and operate the gateway, plus the boundaries that keep it from becoming a host-access tool. Commands below use GATEWAY, you, ifd-dev and devpool as placeholders.

Phase 1. v0.2.0. Incus 6.0 on Ubuntu 24.04. Go 1.26+.

Version 0.2.0. Download the Linux amd64 or macOS arm64 archive and its checksums from GitHub Releases, or build from source. The CLI binary and systemd service are named incus-for-devs.

Overview

incus.ssh is one Go executable with two modes. Server mode runs a private SSH listener beside Incus. Client mode invokes your installed OpenSSH with strict checking and no forwarding. Plain ssh works without the client.

The server maps a configured app username and public key to a fixed Incus project. It parses a small management grammar into fixed argument vectors and runs incus over the local socket. A guest command executes through /bin/sh -lc inside a container the user owns. No host shell is involved.

Phase 1 supports create, list, shell, start, stop, restart and remove. resume is an alias of start. New containers default to 1 CPU, 2GiB memory and 256 processes; the operator's values are per-container maxima. Names are fruit-based unless you pass --name=.

Requirements

  • Linux host with Incus installed and initialised
  • A storage pool and a managed bridge network matching the templates, or edited templates (OVN is not supported)
  • An approved image cached locally in Incus
  • Root access for installation and project preparation
  • Go 1.26 or newer to build
  • OpenSSH on client machines; the compiled client is optional

The shipped profile expects a pool named devpool and a bridge named incusbr0. incusbr0 is also fixed in the project's restricted.networks.access. If you use different names, update the project and profile together. The setup command checks these; it does not create the pool or network.

Guest network policy is operator work. The repository does not install a firewall. Block guest access to host services, private networks and cloud metadata endpoints, and allow only the DNS and egress the containers need. Test the rules before handing out shells.

Build and test

Build and test on an approved Linux development host, not on the target host.

git clone https://github.com/4nkitd/incus.ssh.git
cd incus.ssh

go mod verify
go test ./...
go test -race ./...
go vet ./...
go build -trimpath -o bin/incus-for-devs ./cmd/incus-for-devs

A client binary for another platform is optional and must use a different output name. The server itself runs on Linux; the Darwin build is a client only. Windows builds are not supported. Do not write the Darwin build to bin/incus-for-devs or replace the Linux binary on the host with it. 

# optional client-only build; note the distinct output name
GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 \
  go build -trimpath -o bin/incus-for-devs-darwin-arm64 ./cmd/incus-for-devs

Unit and SSH integration tests use temporary keys and a fake backend. They do not need Incus. Real lifecycle testing needs a dedicated project and disposable container names.

Prepare Incus

Create a dedicated project and fixed profile. The example restricts privilege, nesting, low-level configuration, host disk devices and proxy devices. Containers default to one CPU, 2 GiB and 256 processes, with operator maxima of two CPUs, 4 GiB and 512 processes. 

incus project create ifd-dev
incus project edit ifd-dev < deploy/project.yaml
incus --project ifd-dev profile create ifd
incus --project ifd-dev profile edit ifd < deploy/profile.yaml

# cache an image and use its local alias in the configuration
incus image copy images:ubuntu/24.04 local: --alias ifd-ubuntu-24-04

incus project show ifd-dev
incus --project ifd-dev profile show ifd

Do not enable limits.memory.swap while the project blocks low-level configuration; Incus 6 classifies it as a low-level option and rejects the launch. The profile intentionally omits it.

The setup command

After building on Linux, setup performs the same project and profile preparation with checks. Its default is a plan: it checks the daemon, pool, bridge and cached image, and changes nothing. --apply is explicit, requires root, and is the only mode that creates resources. 

./bin/incus-for-devs setup --templates deploy
sudo ./bin/incus-for-devs setup --templates deploy --apply \
  --project ifd-dev --profile ifd \
  --pool devpool --network incusbr0

Run setup from an extracted Linux archive containing bin/incus-for-devs and deploy/, or from a source checkout after building. An installed binary still needs --templates pointing at the deployment templates.

FlagMeaning
--templates DIRDirectory with project.yaml and profile.yaml. Defaults to deploy; any other value must be an absolute path.
--applyCreate missing project and profile resources. Without it, setup only prints a plan. Requires root.
--project, --profileNames to prepare. Defaults are ifd-dev and ifd. Each is a lowercase slug of at most 48 characters; default is rejected.
--pool, --networkExisting storage pool and managed bridge the templates must reference exactly. Defaults are devpool and incusbr0. Only bridge networks are accepted; OVN is rejected.
--imageA cached local alias, an alias with a local: prefix, or a 64-character fingerprint. Defaults to ifd-ubuntu-24-04. Remote references such as images:ubuntu/24.04 are rejected.
--config FILERead only the image field from a gateway JSON config. It overrides --image.
--incusAbsolute path to the Incus CLI. Defaults to /usr/bin/incus. Root runs require a trusted, root-owned executable and directories that are not writable by group or others.

The plan verifies that the Incus daemon is reachable and trusted, the pool and network exist, the network is a managed bridge, and the image alias or fingerprint resolves to a cached container image. It does not parse the templates, so template problems are reported only at apply. The account running setup needs access to the local Incus socket; apply requires root.

Apply validates the templates as strict typed YAML: only known top-level keys are accepted, duplicate keys, aliases and multiple documents are rejected, and config values must be non-null scalars. Template and config files must be regular, non-symlink files not writable by group or others. The project must set the required restricted and container-only settings, including features.storage.volumes=true, features.storage.buckets=false and exactly one allowed managed bridge. The shipped template also includes container-only resource limits. The profile must set the fixed security values and define exactly one root disk and one managed NIC.

Existing project and profile resources that match exactly are left unchanged. Any mismatch fails with a difference report and is never overwritten or deleted. Apply creates only missing resources; if a later create fails after an earlier one succeeded, setup reports the partial state and asks you to re-run to reconcile. It verifies the result after creating. It never installs packages, writes systemd or SSH configuration, creates pools or networks, downloads images, or changes anything outside the configured project and profile.

The pool, bridge and local image must already exist. Use the manual commands above if you prefer to manage project and profile edits yourself.

Configure

Start from config.example.json. It is a template, not a working deployment. Replace the placeholder key, set the image to the cached alias used by setup (for example local:ifd-ubuntu-24-04), choose a listener, and point the host key at the path you will generate. The example's 127.0.0.1 listener is reachable only on the host; for a remote client, bind the gateway's tailnet address instead. 

{
  "listen": "127.0.0.1:2222",
  "host_key": "/var/lib/incus-for-devs/host.key",
  "incus_binary": "/usr/bin/incus",
  "image": "local:ifd-ubuntu-24-04",
  "profile": "ifd",
  "operation_timeout_seconds": 120,
  "max_sessions": 8,
  "limits": {
    "max_instances": 1,
    "cpu": 2,
    "memory": "4GiB",
    "processes": 512
  },
  "users": [
    {
      "name": "you",
      "project": "ifd-dev",
      "authorized_keys": ["ssh-ed25519 AAAA... you@example"]
    }
  ]
}
FieldMeaning
listenLoopback, a Tailscale IPv6 address, or an IPv4 address in 100.64.0.0/10; port 1024-65535. This is a range check, not proof of tailnet membership. Wildcard and public binds are rejected.
host_keyAbsolute path to the persistent SSH host key.
incus_binaryAbsolute path to the Incus CLI.
image, profileOperator-fixed image and profile. Clients cannot override them. The image should be the cached local alias checked by setup.
limitsPer-container maxima for CPU, memory and processes. The defaults a client gets when it requests nothing are 1 CPU, 2GiB and 256 processes. max_instances counts instances in the project.
usersExactly one app user: name, project and 1-16 public keys.

Configuration must be a regular file not writable by group or others. Keys must be ordinary single-line public keys; authorized-key options, certificates and duplicate keys are rejected. Omit limits.disk when the storage backend cannot enforce a quota; explicit --disk requests then fail.

Install the service account and host key

useradd --system --user-group \
  --home-dir /var/lib/incus-for-devs \
  --shell /usr/sbin/nologin incus-for-devs

install -d -o incus-for-devs -g incus-for-devs -m 0700 /var/lib/incus-for-devs
install -d -o root -g incus-for-devs -m 0750 /etc/incus-for-devs
install -o root -g root -m 0755 bin/incus-for-devs /usr/local/bin/incus-for-devs
install -o root -g incus-for-devs -m 0640 prepared-config.json /etc/incus-for-devs/config.json

runuser -u incus-for-devs -- /usr/local/bin/incus-for-devs keygen \
  --path /var/lib/incus-for-devs/host.key

keygen creates a new Ed25519 key with mode 0600 and refuses to overwrite an existing file. Keep it across upgrades. Losing it changes the fingerprint clients trust.

Run as a service

The repository includes a systemd unit. It runs a nologin account and grants incus-admin only as a supplementary group to the service process. 

install -o root -g root -m 0644 deploy/incus-for-devs.service \
  /etc/systemd/system/incus-for-devs.service
systemctl daemon-reload
systemctl enable --now incus-for-devs.service
systemctl status incus-for-devs.service --no-pager

A service that is “active” and a listening socket prove very little. Complete the first-login checks below before treating the deployment as working.

First login

Obtain the gateway's host-key fingerprint through trusted administrative access. Compare it with what the listener presents, then pin it. Do not skip this because the listener is on a private network. 

ssh -p 2222 you@GATEWAY help
ssh -p 2222 you@GATEWAY whoami --json
ssh -p 2222 you@GATEWAY new --name=operator-check --cpu=1 --memory=2GiB
ssh -p 2222 you@GATEWAY ssh operator-check 'uname -a'
ssh -t -p 2222 you@GATEWAY ssh operator-check
ssh -p 2222 you@GATEWAY stop operator-check
ssh -p 2222 you@GATEWAY start operator-check

When operator-check is confirmed disposable:

ssh -p 2222 you@GATEWAY rm operator-check
Removal is permanent. rm force-deletes the container and its root filesystem. It is not a pause and it cannot be undone from the gateway.

Commands

SyntaxBehavior
help [all|COMMAND] [--json]Show the supported subset or one command. ? aliases help.
whoami [--json]Return the authenticated app user and project.
new [--name=NAME] [--cpu=N] [--memory=SIZE] [--processes=N] [--disk=SIZE] [--json]Create and start an owned container with the configured image and profile. Omitted values use the defaults.
ls [-l] [--json] [name-or-glob]List owned containers. -l has six fields: name, status, CPU, memory, processes and disk.
ssh NAME [COMMAND...]Open a guest shell or run a guest command. Streams stdin, stdout, stderr and exit status.
start NAME [--json]Start a stopped owned container. resume is an alias.
stop NAME [--json]Gracefully stop an owned container. Files persist; process state does not.
restart NAME [--json]Gracefully restart an owned container. Data persists; processes restart.
resume NAME [--json]Alias of start. Process state is not restored.
rm [--json] NAME...Permanently delete each named owned container and its filesystem.

Value flags require =: --cpu=1 works, --cpu 1 does not. --json is a bare flag. Names use 1-63 lowercase letters, digits or hyphens, start with a letter and end with a letter or digit. Sizes need a positive integer and a unit such as 512MiB or 2GB. Unknown and duplicate flags fail.

Without --name=, new picks a fruit name such as mango. Bare fruit names are used first. Only when every bare name is taken does it fall back to suffixed names such as kiwi-2, using the lowest free suffix from 2 to 100 for each fruit. A name supplied with --name= is used exactly as given and fails if it already exists.

New containers default to 1 CPU, 2GiB memory and 256 processes. A request may go up to the operator's maxima. Memory is admitted only if the host has room after a 1GiB reserve and after counting memory already committed to the project; the check fails closed if host memory cannot be read. Starting a stopped instance requires fresh admission. Restarting a running instance revalidates operator ceilings without charging its resident memory again. Lowered ceilings can prevent an instance from starting or restarting. CPU maxima are per-container caps, not a scheduler: the gateway does not balance or reserve CPU time. The host policy is about RAM, not swap; swap is not configured, counted or promised.

After ssh NAME, everything belongs to the guest, including --json. The guest command runs through /bin/sh -lc. Quote the complete command locally when it contains pipes, variables or spaces.

vm_name and vms are compatibility names for containers. The backend creates Incus containers, not virtual machines.

Optional Go client

Client mode replaces itself with OpenSSH. It forces strict host-key checking, disables agent forwarding and clears forwardings. It uses your SSH configuration and agent. Client options come before the management command. 

./bin/incus-for-devs --target you@GATEWAY --port 2222 help
./bin/incus-for-devs --target you@GATEWAY --port 2222 ls --json
./bin/incus-for-devs --target you@GATEWAY --port 2222 ssh demo
./bin/incus-for-devs --target you@GATEWAY --port 2222 ssh demo 'printf "%s\n" "hello world"'

INCUS_FOR_DEVS_TARGET=your-ssh-alias ./bin/incus-for-devs ls --json

With one argument after ssh NAME, the client sends it as the complete guest command. With several arguments, it quotes each one. Omitting --port leaves the port to OpenSSH configuration; there is no implicit 2222.

Security model

Phase 1 is a single trusted-user gateway for unprivileged development containers. It is not a multiuser service, a hostile-tenant sandbox, or a VM isolation boundary.

  • Authentication requires both the configured username and a registered public key. Tailscale provides transport, not app identity.
  • The listener accepts loopback, Tailscale's IPv6 prefix, or IPv4 addresses in 100.64.0.0/10, on ports 1024-65535. That checks the address range, not tailnet membership or ACLs.
  • The service's Incus socket access is effectively host-root authority. The nologin account and systemd sandbox restrict how it is reached, not what it can do.
  • Containers are unprivileged with an isolated UID map, no nesting, no arbitrary host disk or path mounts and no proxy devices. They share the host kernel.
  • Clients cannot choose a project, profile, image, host mount or raw Incus flag.
  • Every list, shell and lifecycle request checks the container's owner label and project.
  • Only SSH session channels are accepted. Agent, X11, environment, TCP forwarding and subsystem requests are refused.
  • CPU and memory maxima are resource limits, not scheduling guarantees. Creation and starting stopped instances check host memory. An active restart revalidates limits without charging resident memory twice. Admission is not a reservation.
  • Swap is outside the host policy: the gateway does not configure it, count it as capacity or promise it.
  • A directory storage pool may not enforce a disk quota. CPU and memory caps do not stop a full disk.
  • Persistence across a graceful stop and start is not a backup. Host reboot recovery is not verified.

The setup command only prepares the restricted project and fixed profile, and only when run with root and --apply. It creates missing resources, never edits or deletes existing ones, and verifies the result. It does not install packages, change host SSH, firewall or network configuration, create pools or networks, or download images. Never expose the Incus socket or incus-admin group to a client or guest. The project restrictions depend on the operator keeping that boundary intact.

Limits

CapabilityStatus
pause, RAM checkpointUnsupported. Incus freeze (operator-only) keeps RAM; stop loses process state.
SFTP, SCP, rsyncNo file-transfer endpoint. Do not point those tools at the management port.
Previews, sharingNot implemented.
Docker, nested containersNot supported. The project and profile block nesting and low-level configuration.
OpenTunnel-style exposureNot implemented. There is no public tunnel or per-container public hostname.
Direct guest hostnamesNot implemented. Use ssh NAME through the gateway.
OVN networksNot supported. Setup accepts only a managed bridge network.
MultiuserExactly one configured app user.
Custom images, profiles, projectsOperator-only. No client interface.
Tags, snapshots, billingNot implemented.
Host reboot recoveryNot verified. Guest autostart is disabled.

These are Phase 1 boundaries, not promises for a later phase. Features such as pause, file transfer, previews, Docker, public tunnels or multiuser admission would each need a separate design and trust-boundary review.

Troubleshooting

SymptomCheck
Permission denied (publickey)The username must match a configured app user and the presented key must be registered for it. Tailnet membership is not enough.
Host key verification failedCompare the listener fingerprint with the trusted host key. Do not disable checking.
project instance limit reachedThe limit counts every instance in the project, while ls shows only containers you own. Check the project through operator Incus access before deleting anything.
CPU request ... exceeds maximumRequest at or below the configured ceiling, with --cpu=N. The effective ceiling may also be lowered to the host's CPU count.
process request ... exceeds maximumLower --processes=N, or raise limits.processes in the operator configuration.
host cannot admit ...Host memory after the 1GiB reserve and existing project commitments is too small, or the stored instance limit no longer fits. Request less memory or free capacity; this is not a swap problem.
Start or restart refuses an instance limitStart and restart revalidate the stored CPU, memory and process limits against current maxima. Recreate the instance within the current limits, or restore deliberate operator limits.
instance name unavailableYour --name= already exists in the project. Pick another name or omit the flag for a generated fruit name.
disk quota is unavailableThe operator did not configure or verify disk quota support. Omit --disk or fix the backing storage.
invalid instance nameUse 1-63 lowercase letters, digits or hyphens, starting with a letter and ending with a letter or digit.
Setup reports a template mismatchThe pool or network flag does not match the template, or a required setting is missing. Fix the templates or flags before running apply.
Setup verification mentions storage bucketsThe project must set features.storage.buckets=false. A project created with buckets enabled does not match the template; reconcile it under change control.
Setup refuses an existing project or profileThe live resource differs from the template. Setup prints the difference and never overwrites or deletes it. Review the diff, then reconcile or remove the resource under change control and re-run apply.
Setup says the image is not available locallyCache the image in Incus first, or pass the exact local alias or fingerprint. Remote references are rejected and never downloaded.
setup V1 requires a managed bridge networkOVN is not supported in Phase 1. Point --network at a managed bridge and keep the template in sync.
--apply requires rootRun setup with the privileges needed to create the project and profile, or run it without --apply for a plan.
pause is unsupportedExpected. Stop the container or use operator-only Incus freeze; neither restores RAM state to disk.
client mode requires OpenSSH on PATHInstall OpenSSH or use stock ssh directly.
Guest output is truncatedOlder builds could lose output on a blocked stream. Use a current build; the session now aborts instead of reporting false success.

Development

Package responsibilities: internal/gateway handles SSH authentication and sessions, internal/command parses and dispatches the management grammar, internal/incus enforces ownership, admission and fixed CLI arguments, internal/names generates fruit names, internal/setup prepares Incus, and internal/app loads configuration and starts the server.

Run gofmt, tests, the race detector and go vet before opening a pull request. Update CHANGELOG.md for behavior changes, and keep the site in docs/ in sync with the README. Read CONTRIBUTING.md and SECURITY.md. Security reports should not be public issues.
